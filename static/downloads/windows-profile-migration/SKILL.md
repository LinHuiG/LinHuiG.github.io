# Windows用户环境迁移

适用于旧机到新机或不同用户配置之间的恢复。保持用户指定的软件、版本、路径、延后/取消范围；使用前获取本次机器实际信息，不沿用参考案例的盘号、用户名和目录。

## 开始前确认的事实

- 哪台机器在运行，源备份和目标卷是谁；确认卷标、容量、硬件身份，不能只看盘符。
- 用户已验收、正在使用、取消、暂缓及明确禁止操作的应用。用户自行修好的应用不再纳入自动修复。
- 区分配置、用户数据、附件、缓存、凭据存储；盘符映射必须覆盖项目内配置、快捷方式、启动项和虚拟机列表。
- 旧机尚可用时，优先核实官方跨机导出、机器密钥、凭据管理器和恢复验证，之后才能建议退役旧机。
- SSH不能只复制密钥：核对实际客户端及HOME、config中的旧用户/盘符引用和有效Host匹配，再在授权范围内用禁止密码交互且保留主机身份校验的方式验证认证。命令行成功与IDE拉取成功分开记录。
- 不只盘点安装程序：同时检查便携工具、托盘/任务栏组件、登录启动项、全局快捷键、hosts和环境变量；发现候选后结合用户范围筛选，不盲目恢复所有启动项。

## 优先级与带宽

建立单一安装恢复队列，记录用户优先级、已有安装包、下载体积、前置依赖、需交互环节、暂缓/取消状态。先恢复关键工作能力，低优先级大下载不应占满关键任务带宽。受登录、缺盘阻塞的单项不阻塞其他可执行项。用户说“继续”时重新处理暂缓范围，不能遗忘之前的工作。

低带宽是持续约束：以实测速率估时，间隔采样文件字节数并结合进程/错误日志判断。下载未结束不等于卡死；有持续增长就保留下载，只有明确异常证据才重试。用户提供安装包后核验本地包并防止重复任务。

## 恢复与验收

1. 读取应用日志、进程信息和实际写入文件确定生效目录。MSIX、注册表/文件虚拟化可能让工具子进程与桌面启动看到不同目录；不要仅根据APPDATA推断。
2. 恢复前备份目标当前数据。应用会在退出时写回配置时，等待用户退出或用应用支持的快照机制，避免与用户新修改竞争。
3. SQLite使用受支持的备份或冷备份，关联WAL/SHM一起考虑。新旧数据共存时，在副本中按主键与schema合并，新记录冲突策略应明确。原库损坏时先定位可读范围，保留原件和失败证据。
4. 跨盘复制禁止默认镜像删除。去重备份必须用映射重建原目录。对已存在目标先比较内容；不同内容保留双方，不能仅凭时间戳或文件大小覆盖。
5. 配置文件已写入、应用已加载、代表功能验证、用户验收是不同状态。只报告已获得的证据，不把quick_check、文件数量或服务存在当作完整功能恢复。
6. 按用户工作流做分项验收：IDE全局配置与项目同步；会话工具的原始会话、索引、项目注册和归属；浏览器的个人资料、密码、扩展、书签和旧标签页；聊天工具的消息、新增数据与附件；小工具的快捷键、显示和启动项。第一次失败后梳理相关层面的证据缺口，不只修复当前症状。
7. hosts恢复先备份新机文件，比较有效条目并检查冲突后合并，再验证名称解析；系统代理和环境变量亦应比较后更新，避免整体覆盖新机设置。

遇到凭据、聊天数据、开发工具链或运行身份问题时，读取[专项处理要点](references/pitfalls.md)。

## 下载、安装及开发工具链

- 从官方来源确认安装方式、兼容性、版本和签名；不同安装器的静默参数和路径引用规则不能套用。
- 低网速下依据文件增长和进程判断进度，不因等待久而重启或重复下载。用户提供安装包后优先验证该包。
- Gradle Wrapper、项目指定版本和原可用组合优先于IDE默认最新版；分清Gradle安装目录、用户缓存目录、Gradle JVM和项目语言级别。
- 先做版本/离线配置加载检查，依赖解析或编译单独记录。不运行发布、生产服务或用户数据变更来验证迁移。

## 收尾清理

用户授权清理且验收完成后：
- 建立具体文件清单，标注大小、保留副本、哈希证据和删除理由。先形成计划，再执行。
- 仅清理确认重复的安装包、可再生失败下载、被最终验证产物替代的工作副本等。不能把“旧”或“大”当删除理由。
- 保留唯一原始备份、无法再导出的机器凭据资料、用户新数据，以及用户要求保留的脚本/文档。无法确认重复的备份保留并说明。
- 删除前重新校验文件未变化、解析后的路径在授权工作区内、无链接越界；优先逐文件删除，不拼接跨shell递归删除命令。
- 输出已删文件与实际释放的逻辑字节数，不承诺等同磁盘可用空间变化。清理后更新单一权威验收单，旧进度保留为历史。

技能不授予额外权限；遵守本会话的应用操作、联网、键鼠、重启及外部写入边界。
